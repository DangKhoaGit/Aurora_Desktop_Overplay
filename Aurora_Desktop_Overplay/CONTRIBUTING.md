# Contributing

1. Tạo issue có acceptance criteria trước thay đổi lớn.
2. Dùng nhánh `feat/<issue>-<slug>`, `fix/<issue>-<slug>` hoặc `docs/<issue>-<slug>`.
3. Chạy build Release và test trước pull request.
4. Không commit secret, certificate, media có bản quyền hoặc dữ liệu AppData.
5. Dùng Conventional Commits.

Mọi pull request phải giữ `Core` độc lập với WPF/Win32 và nêu ảnh hưởng hiệu năng nếu thay đổi renderer.
